\section{Experiments}
\label{sec:experiments}

This section reports the empirical evaluation of PY-IDR. The simulation
results in \S\ref{sec:sim-design}--\S\ref{sec:sim-py-vs-dp} are based on the
``submission-scale'' Monte Carlo sweep specified below; corresponding tables
and figures are computed from a recorded seed ledger and are reproducible
end-to-end from a clean checkout (\S\ref{sec:runtime}). The five real-data
applications in \S\ref{sec:real} are described as a planned protocol; each
dataset's per-cell numbers will be filled in once the upstream data manifests
land (plan~08 of the implementation roadmap).

\paragraph{Implementation scope.}
The submission-scale sweep evaluates PY-IDR (MCMC) against two implemented
comparators (Vanilla IDR via the pairwise EM of \citet{LiBrownHuangBickel2011}
aggregated by mean idr; MaxRank in the spirit of \citet{Philtron2018MaRR})
across the five simulation regimes S1--S5 plus the S5-sparse stress test.
The cells use $K=2$ replicates, $n=400$ features per replicate, and
$R=20$ Monte Carlo replications per cell. The original protocol specifies
$K\in\{2,5,10,50\}\times n\in\{2{,}000,10{,}000,50{,}000\}\times R=100$;
the GPU run that fills the larger cells is queued for the production
follow-on and the scale-down is documented per cell so submission readers
can interpolate. Methods not yet integrated in the package (eCV, nestedIDR,
ChIP-R, GMCM-AD, BNP-Archimedean) are flagged in
Table~\ref{tab:sim-fdr} as ``not yet integrated'' rather than reported as
placeholders.

\subsection{Simulation design}
\label{sec:sim-design}

\input{tables/table_sim_design}

The simulation design extends the original IDR benchmark of \citet{LiBrownHuangBickel2011} with a heavy-tailed regime S5. Regimes S1--S4 are reproduced as planned IDR-style benchmarks, parameterizing the reproducible-component copula as Gaussian with correlation $\rho$ and reproducible mass $\pi^*$ as listed in Table~\ref{tab:sim-design}. Regime S5 introduces tail-dependent signal copulas drawn equally from $t_5$, Clayton, and Gumbel families with matched Kendall's tau, calibrated so that the bivariate Spearman rank correlation under each family is comparable across families. The S5-sparse stress-test variant uses $\pi^*=0.10$ for ROC and precision-recall evaluation, while the primary S5 table uses $\pi^*=0.30$.

The full protocol evaluates each regime at $K \in \{2,5,10,50\}$ and $n \in \{2{,}000,10{,}000,50{,}000\}$, giving a $5\times4\times3$ factorial design with $R=100$ Monte Carlo replications per cell. The submission-scale run reported here covers the $K=2$, $n=400$, $R=20$ slice of this design with a recorded seed ledger; the remaining cells are queued for the GPU production run. For every replication, the simulation output stores the true class labels, true cluster assignments, true copula family and parameters, marginal transformations, rank-tie information, and all posterior decision summaries needed to reproduce tables and figures. Marginal distributions are shared Gaussian for S1--S2, heterogeneous Gaussian for S3--S4, skewed or heavy-tailed heterogeneous marginals for S5, and transformed to observed scores before marginal modeling.

\subsection{Comparators}
\label{sec:sim-comparators}

The submission-scale sweep evaluates the three comparators currently integrated
in the open-source package; the remaining comparators are flagged as future
work in Tables~\ref{tab:sim-fdr}--\ref{tab:sim-power} and in
\S\ref{sec:sim-sens}.
\begin{itemize}[leftmargin=*]
\item \textbf{Vanilla IDR} \citep{LiBrownHuangBickel2011}, applied pairwise
across all $\binom{K}{2}$ replicate pairs of each replicate and aggregated by
averaging the per-pair local idr; the package wires this through the same
\texttt{run\_replicate} dispatcher as PY-IDR so the long-format result CSV is
directly compatible.
\item \textbf{MaxRank} in the spirit of \citet{Philtron2018MaRR}, computing the
worst per-replicate rank of each feature scaled to $[1/n, 1]$ as a
local-idr-like score. The implementation skips the NPMLE mixture-fit step;
the resulting score is a sortable ranking, not a calibrated posterior
probability, and is therefore reported only where the metric is invariant
to monotone score transforms (ROC, PR).
\item \textbf{PY-IDR (MCMC)}, Algorithm~\ref{alg:mcmc} with $H=5$ auxiliary
atoms, four overdispersed chains (two in the submission-scale slice), and an
EM warm start from the pairwise Vanilla IDR seed (\S\ref{sec:hyperpriors}).
\end{itemize}
The remaining comparators referenced in Table~\ref{tab:related-work} (eCV,
nestedIDR, ChIP-R, GMCM-AD, BNP-Archimedean) and the variational alternative
PY-IDR~(VI) are not yet integrated in the open-source package as of the
submission-scale run; their rows in Table~\ref{tab:sim-fdr} and
Table~\ref{tab:sim-power} are marked accordingly. Author-code verification,
licensing, and input-format compatibility are recorded in the project's
\texttt{open-questions} ledger.

\subsection{Metrics}
\label{sec:sim-metrics}

Primary metrics are realized FDR at nominal $\alpha=0.05$, power at the same
nominal level, posterior contraction in Hellinger distance to the true
reproducible-component copula where truth is known, area under the ROC curve,
area under the precision-recall curve, and calibration of posterior local-idr
thresholds against realized FDR. Secondary metrics are wall-clock time,
effective sample size per second, posterior split-$\widehat R$, number of
active clusters, posterior mass on the correct cluster count, local-idr
credible-band calibration, and decision stability across seeds. Monte Carlo
tables report means with Monte Carlo standard errors (computed across the
$R=20$ replicates per cell); calibration plots include 95\% bootstrap bands.
Posterior predictive checks planned for the production-scale run include
marginal rank calibration, pairwise Kendall/Spearman diagnostics, posterior
predictive cluster-size distributions, and failure-case summaries for empty
or near-empty rejection sets.

\paragraph{Acceptance criteria (verdict ledger).}
The submission-scale sweep produces a structured \emph{verdict ledger} that
records the outcome (\texttt{pass} / \texttt{warn} / \texttt{fail} /
\texttt{insufficient\_data}) of three pre-registered hypotheses against the
recorded numerical results: \textbf{H1} PY-IDR controls realized FDR at
nominal $\alpha$ within a documented slack across regimes; \textbf{H2}
PY-IDR (T$>$1) achieves higher power than pairwise Vanilla IDR on the
heavy-tail regime S5; \textbf{H3} PY-IDR (T$=$1) achieves higher power than
MaxRank on the canonical regime S1. The ledger lives at
\texttt{verdicts.json} in the run directory and is the source-of-truth for
the empirical claims in \S\ref{sec:sim-insights}.

\subsection{Empirical insights}
\label{sec:sim-insights}

We summarise the headline empirical findings from the submission-scale
simulation sweep below. Each claim is anchored on a row of the verdict
ledger (\texttt{verdicts.json}); the per-cell numerical values backing each
claim are in Tables~\ref{tab:sim-fdr} and \ref{tab:sim-power}.

\begin{itemize}[leftmargin=*]
\item \textbf{H1 --- FDR control across Gaussian regimes.}
PY-IDR (MCMC) controls realized FDR at the nominal $\alpha=0.05$ level
within a documented Monte Carlo slack across the Gaussian-copula regimes
S1, S2, S3, and S4. The mean realized FDR at $\alpha=0.05$ is reported in
Table~\ref{tab:sim-fdr}; the verdict ledger records H1 as
\texttt{pass}/\texttt{warn} per regime, with isolated above-slack warnings
flagged at the smallest $n$ on the marginal-mismatch regime~S4.
\item \textbf{H2 --- Heavy-tail dominance over Vanilla IDR on S5.}
PY-IDR (MCMC) with the multi-cluster Pólya-urn chain achieves higher power
than the pairwise Vanilla IDR aggregator on the heavy-tail regime S5 at the
same realized FDR. The verdict ledger records H2 as \texttt{pass} for the
S5 cell of Table~\ref{tab:sim-power}.
\item \textbf{H3 --- PY-IDR dominates the non-parametric MaxRank baseline on
S1.}
PY-IDR (MCMC) achieves higher power than MaxRank on the canonical Gaussian
regime S1 at the same realized FDR. The verdict ledger records H3 as
\texttt{pass} for the S1 cell of Table~\ref{tab:sim-power}.
\end{itemize}

\paragraph{Diagnostic posture.}
Across the 100 PY-IDR cells in the submission-scale sweep
($5\text{ regimes}\times20\text{ replicates}$), the chain driver records the
divergent-transition fraction via \texttt{ChainResult.num\_divergent\_transitions};
the recorded fraction is below the §3.3.1 threshold of $0.5\%$ on every cell.
Split-$\widehat R$ and effective sample sizes are computed by ArviZ on the
recorded posterior trace; the submission-scale two-chain run reports them as
advisory rather than as pass/warn/fail thresholds (the latter require $\ge 4$
overdispersed chains per §3.3.1). The production-scale GPU run will use four
overdispersed chains and the strict thresholds.

\subsection{Ablations and sensitivity analyses}
\label{sec:sim-sens}

The submission-scale sweep exercises the central PY-vs-DP and heavy-tail
ablations \emph{de facto}: regime S5 routes through the multi-cluster
Pólya-urn chain ($T>1$) while S1--S4 route through the $T{=}1$ fast path,
and the multi-cluster path's atomic-type registry covers all four atomic
families ($\{\text{Gauss}, t_5, \text{Clayton}, \text{Gumbel}\}$). Targeted
sensitivity analyses on the LKJ shape $\eta\in\{1,2,5\}$, the auxiliary-atom
count $H\in\{1,3,5,10\}$, the Bernstein-degree prior grid, and the
reproducible-mass prior on $\pi$ are queued for the production-scale GPU run.
Planned component-isolation ablations include PY versus DP prior,
Gaussian-only versus heavy-tail atom base, empirical-rank approximation
versus learned marginals, exchangeable versus factor-structured correlation
classes, and pairwise aggregation versus joint $K$-replicate modeling.
Planned stress tests cover weakly dependent irreproducible components, high
tie rates, missing replicates, near-singular correlation structures,
high-dimensional $K$, and marginal misspecification.

\subsection{Real-data evaluation (planned)}
\label{sec:real}

\input{tables/table_datasets}

The five datasets summarised in Table~\ref{tab:datasets} span the principal
application domains of multi-replicate IDR. As of this submission the
upstream data manifests are queued for plan~08; the prose below describes the
planned evaluation protocol and reports the structure of the per-dataset
analyses that will be executed once each dataset's data-use clearance, QC
pipeline, and rank-transformation outputs land. Per-dataset numerical results
(Tables~\ref{tab:real-disc}, \ref{tab:real-clusters},
\ref{tab:real-runtime}, Figure~\ref{fig:realdata}) are explicitly placeholders
and are marked as such in their captions.

\paragraph{ENCODE 4 CTCF ChIP-seq.}
The ENCODE 4 release \citep{ENCODE2020Nature} provides standardized ChIP-seq data for the CTCF transcription factor across cell lines, with typical experiments comprising two to six biological replicates and 30{,}000--80{,}000 MACS2 narrow-peak calls per replicate. The planned analysis applies PY-IDR to each multi-replicate experiment, with replicate-aware peak signal scores transformed to ranks before model fitting. Planned outputs are per-peak posterior local idr, reproducible-peak count at IDR $\leq0.05$, and posterior summaries of active dependence regimes. Planned baselines are pairwise vanilla IDR aggregation, eCV, nestedIDR if available, ChIP-R, and MaRR.

\paragraph{ENCODE 4 ATAC-seq.}
ENCODE 4 ATAC-seq experiments comprise two to four biological replicates and 70{,}000--200{,}000 MACS2 broad-peak calls per replicate. The planned setup mirrors CTCF, with additional attention to heavier-tailed score distributions and platform effects across cell lines. Any claim that PY-IDR recovers more peaks than ChIP-R is a planned hypothesis until the analysis is run.

\paragraph{DREAM5 gene-network challenge.}
The DREAM5 challenge \citep{Marbach2012DREAM5} provides ranked predictions from 35 algorithms across reference networks. Replicates here are algorithms rather than biological replicates; the IDR framework provides a planned way to aggregate algorithm predictions into a community-consensus reproducible network. Planned outputs include reproducible-edge counts at IDR $\leq0.05$ and overlap with available gold-standard edges.

\paragraph{Tabula Muris pseudobulk.}
Tabula Muris \citep{TabulaMuris2018} is a single-cell mouse atlas with two sequencing technologies. The planned analysis constructs pseudobulk replicates by aggregating cells within tissue and technology, then applies PY-IDR to identify reproducible differential-expression signatures while modeling technology-specific marginal distributions.

\paragraph{Pan-UKBB GWAS.}
The Pan-UK Biobank resource \citep{Bycroft2018UKB,Karczewski2024PanUKBB} provides ancestry-stratified GWAS summary statistics across multiple ancestry groups and thousands of traits. The planned PY-IDR analysis uses ancestry-specific $z$-scores as replicate-like inputs for selected phenotypes, with $K=6$ ancestry strata when all groups pass QC. The application target is variants reproducibly associated across ancestries at IDR $\leq0.05$; any comparison against EUR-only thresholding is a planned analysis rather than an observed result in this manuscript.

\subsection{Computational scaling and reproducibility}
\label{sec:runtime}

function of $n$ for PY-IDR (MCMC) on regime S1 at $K{=}2$. The analytic

$n\in\{100, 200, 400, 800\}$ cells of the scaling sweep. ESS-per-second
measurements and the full $K\in\{2,5,10\}$ panel are queued for the
production-scale GPU run. VI scales as $O(BKT\bar d)$ per mini-batch update
in the design of \S\ref{sec:vi}; the VI panel is deferred until plan~05's

\paragraph{Reproducibility package.}
Every run lands in a directory \texttt{runs/<run\_id>/} that contains the
sweep CSV (\texttt{results.csv}), the run manifest with the git SHA and
resolved CLI configuration (\texttt{run\_manifest.json}, \texttt{run\_config.json}),
the seed ledger, the per-replicate idr trace NPZ sidecar where applicable
(\texttt{idr\_traces.npz}, consumed by F4), and the verdict ledger
(\texttt{verdicts.json}). The companion script
\texttt{scripts/replay\_run.sh~<run\_dir>} re-executes the run from the
persisted configuration on a clean CPU checkout, and the regression tests
\texttt{tests/repro/test\_replay.py} assert that the replay reproduces the
recorded posterior summary to within $10^{-6}$.
